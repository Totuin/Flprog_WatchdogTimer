# Flprog_WatchdogTimer — программный сторожевой таймер FLProg

**Версия библиотеки:** 1.0.1 (ревизия FLProg от 10.11.2026).

Библиотека отслеживает, выполняется ли основной цикл программы контроллера. В `loop()` вызывают `pool()`, а из обработчика периодического аппаратного таймера — `tick()`. Если `pool()` не вызывается в течение заданного времени, библиотека вызывает необязательный callback и пытается выполнить программный перезапуск контроллера.

## Важные ограничения

- **Это программный watchdog.** Он не сработает, если остановлены аппаратные прерывания или зависла система аппаратного таймера. Для отказоустойчивости при полном зависании нужен аппаратный watchdog конкретного микроконтроллера.
- `tick()` и обработчик, зарегистрированный через `setCallBack()`, обычно выполняются **в контексте прерывания**. Нельзя использовать внутри обработчика `delay()`, `Serial.print()`, ожидание завершения операции и длительные вычисления. Пример исправлен соответственно.
- Значение `checkPeriod` измеряется **секундами**, а `tickPeriod` — **микросекундами**. Ноль не допускается: ошибочная настройка отвергается, сохраняется предыдущая.
- Интервалы следует настраивать в `setup()` из основного кода, а не из ISR; не следует менять периоды одновременно с исполнением обработчика `tick()`. На 8-битных процессорах изменение 32-битного параметра при работающем таймере без внешней синхронизации может быть неатомарным.
- На AVR исторический вариант перезапуска `jmp 0x0000` — **не аппаратный reset**: регистры и периферия могут оставаться в прежнем состоянии. Этот способ сохранён в 1.0.1 для совместимости; в дальнейшем можно отдельно согласовать использование аппаратного watchdog AVR.
- На неподдерживаемой архитектуре после callback аппаратный reset не выполняется. Поддержка перезапуска зависит от платформенных макросов `RT_HW_CORE_*`.

## Использование

```cpp
#include "flprogWatchdogTimer.h"
#include "flprogSystemHardwareTimer.h"

FLProgrogWatchdogTimer watchdog(5); // 5 секунд ожидания активности loop()

void onTimerTick() { watchdog.tick(); } // запускается аппаратным таймером

void setup() {
    initFlprogSystemTimer(onTimerTick);
    setFlprogSystemTimerTickPeriod(10); // микросекунды
    watchdog.setTickPeriod(getFlprogSystemTimerTickPeriod());
}

void loop() {
    watchdog.pool();
    // пользовательская программа
}
```

Полный пример см. `examples/FLProgWatchdogTimer/FLProgWatchdogTimer.ino`.

## Публичные методы

| Имя | Назначение |
|---|---|
| `FLProgrogWatchdogTimer(uint8_t)` | Создание объекта; длительность ожидания в секундах |
| `pool()` | Сигнал, что основной цикл продолжает работать |
| `tick()` | Шаг счётчика; вызывается таймером |
| `setCheckPeriod(uint8_t)` | Время ожидания в секундах (1–255) |
| `setTickPeriod(uint32_t)` | Действительный период тика в микросекундах (больше нуля) |
| `setCallBack(FLProgrogWatchdogTimerEvent)` | Необязательная функция перед программным перезапуском |

Исторические имена `FLProgrogWatchdogTimer` и `FLProgrogWatchdogTimerEvent` намеренно сохранены, несмотря на необычное написание. Для защиты от неявных преобразований конструктор помечен `explicit`; обычный вызов `FLProgrogWatchdogTimer watchdog(5);` не меняется.

## Проверки

Каталог `tests/` содержит автономный C++11 тест и тестовые заглушки для запуска без Arduino-платы. Запуск под Linux с установленным C++-компилятором: `bash tests/run_host_tests.sh`. Это **не** замена компиляции реальной прошивки и аппаратных испытаний на AVR / ESP32 / ESP8266 / STM32 / RP2040.
