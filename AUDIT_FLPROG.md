# Аудит Flprog_WatchdogTimer 1.0.1

**Эталон:** `libraries.zip`, `libraries/Flprog_WatchdogTimer`, версия 1.0.0.
**Область:** только данная библиотека. RT_HW и внешние зависимости — чтение без изменений.

## Подтверждённые ошибки

1. **Деление на ноль:** `calculateTickValue()` делил на `_tickPeriod` без проверки. При `setTickPeriod(0)` возможен сбой.
2. **Переполнение heartbeat:** 16-битный `_checkCounter` увеличивался при каждом `pool()`, а `_oldCheckCounter` сверялся из IRQ. Ровно 65536 вызовов между тиками приводили к ложному определению зависания; чтение 16-битного значения на 8-битном AVR дополнительно неатомарно.
3. **Граница тайм-аута:** старый `tick()` вызывал `execureRestart()` только на тике после достижения `_tickValue`, добавляя один лишний тик. При нецелом отношении интервалов срабатывание могло происходить раньше заданного времени; теперь используется округление вверх.
4. **Опасный пример:** `WatchdogTimerHandler()` выполнял `Serial.print()` и `delay(500)` из контекста аппаратного прерывания, что может привести к зависанию.
5. **Документирование:** в исходнике отсутствовали пояснения о единицах измерения, области исполнения callback, программном характере watchdog.

## Проверено

- `keywords.txt`: до ревизии 8 записей, после 9; верные TAB-разделители, без повторов. Добавлен публичный тип обработчика.
- Публичные имена и сигнатуры не менялись; `explicit` у конструктора запрещает только неявное преобразование.
- Подтверждены тестами: ожидаемое количество тиков, округление, нулевые параметры, быстрое выполнение `loop()`, максимальный `checkPeriod=255`.

## Оставленные ограничения / риски

- Это программный, не аппаратный watchdog. Отказ IRQ не обнаруживается.
- На AVR исходная реализация делает переход на адрес 0 вместо полного системного аппаратного сброса. Оставлено ради совместимости.
- `tick()` выполняется из IRQ. Временные ограничения и допустимость платформенной команды reset/пользовательского callback проверяются отдельно на железе.
- Обновлять периоды желательно только при настройке. Одновременная запись 32-битных конфигурационных полей из основной программы и чтение из ISR не защищена платформенно-специфическим критическим разделом — поведение при произвольной динамической перенастройке не заявлено.
- Полная реальная сборка на AVR, ESP8266, ESP32, STM32, RP2040 в текущей среде не выполнялась.

## Рекомендации к приёмке

1. Проверить обычную компиляцию проекта FLProg с `Flprog_WatchdogTimer 1.0.1` и актуальными `Flprog_Utilites` / `Flprog_HardwareTimer`.
2. На устройстве протестировать условие зависания основного цикла при сохранённых IRQ.
3. Отдельно подтвердить, что перезапуск выбранной платформы соответствует ожиданиям, особенно для AVR.
4. Не использовать блокирующие операции в функции `setCallBack()`.
