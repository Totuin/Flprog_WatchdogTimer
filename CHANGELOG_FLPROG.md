# История ревизии FLProg_WatchdogTimer

## 1.0.1 — 2026-11-10 (кандидат, ожидает компиляции пользователем)

### Исправления

- Устранено деление на ноль при `setTickPeriod(0)`; некорректное значение отвергается.
- Вместо `uint16_t` счётчика вызовов `pool()` добавлен байтовый флаг активности; быстрый `loop()` больше не даёт ложного «нет активности» после переполнения.
- Скорректирован момент срабатывания: строго после рассчитанного количества пустых тиков, без дополнительного тика по старой проверке `!=`.
- Интервал пересчитывается без переполнения, с округлением количества тиков вверх и минимумом в один тик.
- При перенастройке периода начинается новый интервал подсчёта.
- Исправлен пример: убраны `Serial` и `delay` из callback, расширен выбор пинов для нескольких платформ.

### Документирование

- Добавлены русские комментарии к публичному API, режиму работы с прерываниями и платформенным вариантам reset.
- Добавлены `README_RU.md` и `AUDIT_FLPROG.md`.
- Обновлён `keywords.txt`: внесён публичный тип `FLProgrogWatchdogTimerEvent`; все записи проверены.
- Уточнены `sentence`, `paragraph`, `category` и `includes` в `library.properties`.
- Конструктор сделан `explicit` (неявное преобразование целого числа в объект теперь запрещено).

### Совместимость

- Публичные имена классов и методов, типы аргументов, способ создания через `FLProgrogWatchdogTimer watchdog(5);` сохранены.
- Поведение при нулевом периоде **изменено намеренно**: ноль не приводит к сбою/немедленному перезапуску, а игнорируется.
- Сценарии «порог ровно между тиками» теперь срабатывают не раньше заданного времени.
- На AVR оставлен исторический `jmp 0x0000`; аппаратную схему reset в этой ревизии не меняли.

### Статус

- Автономные C++11-тесты (ASan/UBSan): PASS.
- Синтаксис примера на тестовых заглушках: PASS.
- Компиляция Arduino/FLProg в реальной среде: ожидается.
- Аппаратные проверки: не выполнялись.
